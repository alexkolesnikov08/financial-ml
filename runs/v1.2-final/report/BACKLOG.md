# Бэклог v1.3

## Записанные задачи

### 1. Edge-фильтр не подключён в pipeline
- **Статус:** реализован в `backtest.py` (параметры `edge_mu_win`, `edge_mu_loss`), но не подключён в `pipeline.run_one_holdout`.
- **Что нужно:** вычислять `μ_win` и `μ_loss` на OOF-сделках базовой стратегии (средние реализованные движения на выигрышных/убыточных сделках), передавать в `BT.simulate` как `edge_mu_win`/`edge_mu_loss`.
- **Эффект:** динамический порог по ожидаемой доходности, снижение числа сделок с отрицательным ожиданием.

### 2. Больше данных для обучения
- Сейчас 60 дней 5m (~4629 баров). Рассмотреть:
  - 1h (~730 дней, ~4400 торговых баров) — компромисс.
  - 15m (~60 дней, ~1560 баров) — сравнение с 5m.
  - Дневные бары (годы истории) — для проверки стабильности логики.

### 3. Больше данных для проверки
- Увеличить `N_HOLDOUTS` до 4–6 (сдвинуть окна).
- Или перейти на 1h/дневные для большего числа hold-out периодов.

### 4. Отключить/ослабить агрессивные фильтры
- В v1.2 `time_mask`, `trend_mask`, `trailing stop`, `min_hold`, `cooldown` отсекли большинство сделок.
- Рекомендация: по умолчанию `TIME_FILTERS=None`, `THR_HI=None`, `THR_LO=None`, `TRAIL_MULT=None`, `MIN_HOLD=0`, `COOLDOWN=0`, затем подбирать на OOF.

### 5. Feature selection
- 95 фичей на 4530 строк — слишком много. Добавить importance-based или L1-отбор перед обучением.

### 6. Optuna для стратегических параметров
- Подбирать гистерезис, min_hold, trail_mult, cooldown на OOF (multi-objective: final_equity + num_trades).

### 7. Confidence-фильтр
- Покупать только при `p ≥ 0.55` (без time/trend фильтров, чтобы не убить число сделок).

### 8. Формальные тесты (pytest)
- `features.build`, `simulate`, `make_time_mask`, `calibrate` — сейчас покрытия нет.

### 9. Cross-asset расширение
- Генерация кросс-фич обобщена (любой `*_close`), но `rel_strength_5` привязан к первому активу. Сделать per-asset.

### 10. Векторизация `autocorr_ret_1_10`
